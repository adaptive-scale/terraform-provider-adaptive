# adaptive_schedule (Resource)

The `adaptive_schedule` resource defines a recurring window in which access requests for the listed endpoints are decided without a human approver. A schedule with `operation_type = "autoapprove"` grants matching requests; `autoreject` denies them, which is the usual way to close off production outside working hours.

Schedules apply to the users, teams and endpoints they name. A request only matches when it falls inside the window in the schedule's timezone and the schedule is active.

## Example Usage

### Business Hours Auto-Approval

```terraform
resource "adaptive_schedule" "business_hours" {
  name          = "business-hours"
  description   = "Auto-approve staging access during working hours"
  schedule_type = "weekdays"

  start_hour   = 9
  start_minute = 0
  end_hour     = 18
  end_minute   = 0
  timezone     = "America/Los_Angeles"

  users     = ["dev1@example.com", "dev2@example.com"]
  endpoints = [adaptive_endpoint.staging_db.name]
}
```

### Freeze Window

```terraform
resource "adaptive_schedule" "weekend_freeze" {
  name           = "weekend-freeze"
  schedule_type  = "weekends"
  all_day        = true
  operation_type = "autoreject"

  teams     = [adaptive_group.developers.name]
  endpoints = [adaptive_endpoint.prod_db.name]
}
```

### Specific Dates

```terraform
resource "adaptive_schedule" "migration_window" {
  name          = "migration-window"
  schedule_type = "specific"

  specific_dates = [
    "2026-03-14T00:00:00Z",
    "2026-03-15T00:00:00Z",
  ]
  all_day    = true
  expires_at = "2026-04-01T00:00:00Z"

  users           = ["dba@example.com"]
  endpoints       = [adaptive_endpoint.prod_db.name]
  max_access_time = 120
}
```

### Custom Weekdays

```terraform
resource "adaptive_schedule" "oncall_window" {
  name          = "oncall-window"
  schedule_type = "custom"
  weekdays      = ["Saturday", "Sunday"]

  start_hour = 8
  end_hour   = 20
  timezone   = "UTC"

  teams     = [adaptive_group.sre.name]
  endpoints = [adaptive_endpoint.prod_k8s.name]
}
```

`schedule_type` selects which of the pattern arguments matter: `custom` reads `weekdays`, `monthly` reads `start_day`/`end_day`, `specific` reads `specific_dates`, and `weekdays`, `weekends` and `everyday` need none of them. Set `all_day` to cover the whole day instead of the start/end time-of-day arguments.

## Schema

### Required

- `name` (String) Name of the schedule. Must be unique within the workspace.
- `schedule_type` (String) One of: weekdays, weekends, everyday, monthly, specific, custom.

### Optional

- `all_day` (Boolean) Run the full day, ignoring the start/end time-of-day fields.
- `description` (String) Human-readable description of the schedule.
- `end_day` (Number) End day of month (1-31). Used by schedule_type = monthly.
- `end_hour` (Number) Window end hour (0-23). Ignored when all_day is true.
- `end_minute` (Number) Window end minute (0-59). Ignored when all_day is true.
- `endpoints` (List of String) Endpoint (session) names this schedule applies to.
- `expires_at` (String) RFC3339 instant after which the schedule stops applying.
- `is_active` (Boolean) Whether the schedule is active. Defaults to true.
- `max_access_time` (Number) Maximum access time in minutes for sessions approved under this schedule.
- `operation_type` (String) Whether a request covered by this schedule is auto-approved or auto-rejected. One of: autoapprove (default), autoreject.
- `specific_dates` (List of String) RFC3339 timestamps. Used by schedule_type = specific.
- `start_day` (Number) Start day of month (1-31). Used by schedule_type = monthly.
- `start_hour` (Number) Window start hour (0-23). Ignored when all_day is true.
- `start_minute` (Number) Window start minute (0-59). Ignored when all_day is true.
- `teams` (List of String) Team names auto-approved by this schedule.
- `timezone` (String) IANA timezone the window is evaluated in. Empty inherits the workspace default.
- `users` (List of String) User emails auto-approved by this schedule.
- `weekdays` (List of String) Weekday names (e.g. Monday). Used by schedule_type = custom.

### Read-Only

- `id` (String) The ID of this resource.

## Import

Schedules can be imported using the schedule ID:

```shell
terraform import adaptive_schedule.example schedule-id
```

The read endpoint returns a lossy view of a schedule: it reports the name, type, active flag, all-day flag, timezone, operation type and expiry, but not the pattern arguments. Those are left as your configuration wrote them on refresh, and stay empty after an import until you fill them in.
